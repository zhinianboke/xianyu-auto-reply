# AI生成前确认消息

账号管理的“AI回复设置”中可开启“AI生成前发送确认消息”。默认关闭，默认文案为“收到，稍等一下”，默认冷却时间为 30 分钟。

- 确认消息由 AI 引擎在所有本地确定性分支结束后、真正调用模型前触发；议价次数上限等无需模型的回复不会发送确认消息，也不会占用冷却。
- 关键词回复、默认回复、AI 关闭或不在启用时间段、人工接管暂停、已下单用户拦截等流程不会发送确认消息。
- 冷却范围是“账号 + 买家 + 商品”，由 Redis 原子占位，避免多进程或消息突发时重复发送。
- 确认消息发送失败仍保留本次冷却，并继续生成最终 AI 回复，避免持续失败造成刷屏。
- 商品查询、Redis 占位和确认消息发送前后都会复查整段会话接管及“买家 + 商品”AI 暂停；一旦人工接管，不再发送确认消息或调用模型。
- 确认消息的服务端异步回执会与模型调用并行等待；平台安全拦截会写入回复链路 trace，等待超时沿用现有发送语义并完成 Future 清理。
- Redis 不可用时会跳过确认消息，但不会阻断最终 AI 回复。

限制：本功能沿用现有“已下单用户禁止 AI 回复”和人工接管判断，不新增或猜测“已付款且即将离开”等平台状态识别。

## 仅回复宝贝咨询

所有账号的自动回复仅处理携带商品 ID、且商品属于当前账号的咨询。用户确认的系统通知账号 `2222880673631` 和已有官方机器人账号会被提前拦截，即使携带商品 ID 也不回复。无发送者、无商品关联及占位商品 ID 的消息同样跳过；不会进入关键词、AI（含前置确认）或默认回复。

真实买家的无商品关联私聊也不自动回复，需人工处理。现有订单处理、自动发货和人工聊天不因本规则修改。自动回复日志会显示“系统账号，禁止自动回复”或“非宝贝咨询，未关联商品”。本规则按消息携带的商品上下文判断，不宣称能验证对方的真实身份。
